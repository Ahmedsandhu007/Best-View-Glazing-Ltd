Delivery templates {{ store.name }}

What this page does

On OnBuy every listing sits on a delivery template (how fast you dispatch and how long delivery takes). Products from different suppliers need different ones - eBay and Amazon products go out fast, AliExpress ones take longer - so each supplier has its own template. Here you see, per supplier, the template its listings should sit on and how many really do, set the template ids, and move the strays: Plan only counts, Test moves ONE listing and reads it back, Apply moves them all. A listing with no row on the sheet (so no known supplier) is never moved. The handling and delivery times themselves are set on OnBuy, never here. Only Test and Apply change anything, and they ask for the confirmation box.

Run it

Every run reads the store's whole listing catalogue from OnBuy (about 100 requests, a few minutes) and the sheet. OnBuy limits reads, so use it once or twice a day at most.

Plan read only

Counts where every supplier's listings sit and how many are off their template. Changes nothing.

Test on one listing

Moves ONE listing to its supplier's template and reads it back after 10, 30 and 60 seconds: proves OnBuy takes the change. Only that listing changes.

Apply moves listings

Moves every listing that is off its supplier's template (500 per request; each keeps its own price and stock). It refuses when more listings than the limit would move. Listings OnBuy never put live cannot be moved and are skipped.

How it decides

For every live listing of the store

1. Which supplier? From the sheet: the first product tab by the link in its row (an eBay item link = eBay, an Amazon link = Amazon, an AliExpress link = AliExpress), the Amazon tab as Amazon{% if store.id == 'makstore' %}, and the semi store's sheet as AliExpress{% endif %}. A listing with no sheet row is legacy and is left alone.

2. Which template? The id set for that supplier above. No id for a supplier = its listings stay where they are.

3. Move. A listing on another template is sent to its supplier's template with its own price and stock unchanged. OnBuy applies it with a short delay (the read-back right after may still show the old one).

Listings OnBuy created but never put live (price 0.00) answer "SKU does not exist" to every update, so they are skipped. The nightly of Arden and Makstore only does this for listings created during the day.
