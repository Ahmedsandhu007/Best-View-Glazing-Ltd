Help what this is, how to make it work, how to put it online

What this dashboard is

One web page for all the OnBuy stores. It never talks to OnBuy itself and holds no OnBuy password: it only reads what the stores' GitHub jobs have done and starts those same jobs for you (and edits their on/off switches and a few list files). So it is only as good as its link to GitHub - the checklist below shows that link live. Everything that changes a store asks for a tick in a confirmation box first.

2. Run it on your PC Windows, step by step

  1. Install Python (3.11 or newer) from python.org. On the first installer screen tick Add python.exe to PATH. Check: open PowerShell and run python --version.
  2. Install the GitHub CLI from cli.github.com, then sign in once: gh auth login (GitHub.com, HTTPS, "Login with a web browser", use the account that owns the store repositories). Check: gh auth status says "Logged in".
  3. Have the dashboard folder. On this PC it is already at E:\Academics\Dev-Projects\BVG-Site\dashboard. On another PC: git clone https://github.com/bestviewglazing/BVG-Site (the dashboard is its dashboard folder) (after step 2 the CLI lets you clone the private repository).
  4. Start it. Double-click start-dashboard.bat in that folder - the first time it installs what it needs (about a minute), then starts the dashboard and opens your browser. By hand instead: in PowerShell cd E:\Academics\Dev-Projects\BVG-Site\dashboard, then pip install -r requirements.txt (first time only), then python run.py.
  5. Open http://127.0.0.1:8787. Check the table in section 1: the GitHub token and every store should be green.
  6. Leave the black window open while you use the dashboard - it is the dashboard. Close it (or press Ctrl+C in it) to stop. Red text in it is where to look first when a page shows an error.
  7. Settings file (only if you need it). Copy .env.example to .env in the same folder and fill in what you need: GITHUB_TOKEN (when the CLI is not used), DASHBOARD_PASSWORD (a password for the page), DASHBOARD_PORT (another port if 8787 is taken). Restart after changing it.

Only this PC can open 127.0.0.1. The dashboard works only while the PC is on and the black window is open.

3. Put it online so you (and later your team) can open it from anywhere

To be reachable from anywhere the dashboard must run on a computer that is always on. These are the ways, from simplest to most work:

WhereWhat it takesGood for
This PC (now)Nothing more: steps above.You alone, while the PC is on.
A small rented server (VPS) the planRoughly 4 to 6 pounds a month. Copy the folder, set GITHUB_TOKEN and DASHBOARD_PASSWORD, run it as a service behind HTTPS. Step by step in HOSTING.md in the dashboard folder.Always on, a web address of your own, later logins for employees.
Google Cloud RunA Google Cloud account with billing switched on (a one-person dashboard stays inside the free monthly allowance - check Google's current pricing). The folder already has a Dockerfile; one command deploys it (HOSTING.md). Its disk is wiped whenever it restarts, so the "What was pressed" and "Started from here" lists reset; everything real lives in GitHub and is unaffected.Google-hosted, no server to look after.
Google Apps Script not as it isThis dashboard is written in Python; Apps Script runs only JavaScript, each call is limited to a few minutes, and there is no database or file system. It cannot be pasted in. An Apps Script version would be a rewrite of every card (like the eBay orders dashboard you paste and deploy) - possible, but a large piece of work, so it is only worth it if the Google-only route matters more than a rented server.Ask for it if you want it; say which cards matter most.

Whatever the host: set a password first, use HTTPS, and give the token only the access it needs. A classic GitHub token with the repo scope is enough (the CLI's own token already has it).

5. Words used

Dry run / preview / plan
A run that works everything out and reports it but changes nothing. Always do one before the real thing.
Apply
Do it for real on the store's sheet or settings. Needs the confirmation box.
Push
Send what is on the sheet to the live OnBuy listings, so customers see it.
Backup tab
A tab of the store's sheet where a tool copies every row it is about to change or remove, so nothing is lost.
Slot / queue
A store runs one OnBuy job at a time. A job started while another runs waits behind it; a second waiting job would cancel the first, so the dashboard refuses to start one.
Frozen / hold list / protected list
A listing whose stock is held at 0 and which no sync touches, because its OnBuy page shows another product or it is being investigated.
Stale
An automatic job that has not run for longer than it normally takes.
Floor
The lowest price at which a sale or a Buy Box price cut is still allowed: it keeps a minimum profit after OnBuy's commission.
Delivery template
A bundle of handling time, delivery time and cost you set up on OnBuy; every listing sits on one. Each store has its own templates (their ids are per account).
OPC
OnBuy's own code for a product of its catalogue (like PYQX8PS). Support asks for it when a product page misbehaves.
Canary
A small first batch (a few products) done for real before the rest, so a problem shows on three products and not on three hundred.
Resubmit
Send a product to OnBuy again with its content and picture links, so OnBuy's image workers try once more. The listing's price and stock stay as they are.
Repository variable
An on/off switch or number kept in a store's GitHub repository that its jobs read (see Settings). A change applies from the next run.

6. If something goes wrong

  • The page does not open - the black window must be open and show "Uvicorn running". If it says the address is already in use, the dashboard is already running: just open the address. Otherwise set another DASHBOARD_PORT in .env.
  • "GitHub token missing" or a store shows "no" - see the checklist above: sign in with gh auth login as the account that owns the repositories.
  • A button says a run is waiting for the store's slot - wait a few minutes and press again; starting a second waiting run would cancel the first one.
  • The result box stays on "in progress" - GitHub can delay a run by minutes. Open the run's link: it shows the live log. The box follows it for up to 40 minutes.
  • GitHub says rate limit - GitHub allows 5,000 requests an hour per token; wait until the hour turns over.
  • Anything else - the red text in the black window and the run's log on GitHub say what happened; send them to me.
