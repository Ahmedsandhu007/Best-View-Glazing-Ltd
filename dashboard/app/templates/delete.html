Delete by list remove the sheet rows and the OnBuy listings of the SKUs you name - {{ store.name }}

What this page does

Deletes a list of SKUs for good: their rows leave the sheet (copied to a backup tab first) and their OnBuy listings are deleted. Paste or load the list, Check it, Plan it (a dry run that shows what would go and what is held back), then Delete for real. SKUs on open orders and on the frozen lists are never in the list. Only "Delete for real" changes anything, and only after a plan of that exact list finished well.

1. The list

the plan saves the list in the repository and changes nothing else

What it does

  • A SKU of your list that is on the sheet: its row is copied whole to the backup tab, then removed, and its OnBuy listing is deleted. Deleting only the listing would let the next sync create it again.
  • A SKU that is not on the sheet: only its OnBuy listing is deleted.
  • Held back, nothing happens to them: a row that shows stock (unless you tick the box), a SKU on more than one row, a SKU on the hold lists. SKUs on an open order are kept out of the list before it is saved.
  • The plan refuses to go above the list's size, and the real run reads the sheet again right before each delete.
  • OnBuy cannot delete a suspended listing through the API: those are shown after the run, for you to delete by hand.

3. Suspended - only you can delete these

OnBuy's API refuses to delete a suspended listing (its update endpoint even answers "SKU does not exist"), so every tool that meets one names it here: delete it by hand on OnBuy, then tick it off - the dashboard remembers who ticked it and when. A suspended listing cannot sell meanwhile, so none of this is urgent.
